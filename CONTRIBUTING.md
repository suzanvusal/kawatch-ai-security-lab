# Contributing to Kawatch AI Security Lab

Thank you for your interest in contributing.

## Before Starting

Read the README and the documents in `docs/`, especially
`SECURITY_BOUNDARIES.md`.

Use controlled test applications and synthetic data during development.

## Development Principles

- Keep changes small and understandable.
- Include tests for new behavior.
- Document important design decisions.
- Preserve evidence and uncertainty in security findings.
- Never commit real credentials or customer data.
- Do not add destructive or unauthorized assessment behavior.

## Pull Requests

A pull request should explain:

1. What changed.
2. Why the change is needed.
3. How it was tested.
4. Any known limitations or security implications.

Automated checks should pass before a change is merged.

## Reporting Security Issues

Do not publish real credentials, private customer data, or exploitable
details about a third-party system in a public issue.

Use responsible disclosure and an appropriate private reporting channel
when one is available.

## Project Status

This project is experimental. Contributions do not imply that the
software is suitable for production security assessments.
